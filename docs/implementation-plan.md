# 구현 계획

## 우선순위

키가 없는 공개 웹 수집을 1순위로 한다. 공식 API 필드 목록은 유사 기능의 비교 기준이며
공식 API 호출을 구현하기 위한 계획이 아니다. 모든 공식 서비스의 대응 가능 여부를 조사하고,
공개 화면에 없는 기능은 명시적 미지원으로 남긴다. 데이터를 추정 생성하지 않는다.

1. **T001** 조사·사양·구조·검증·task 문서를 PR로 먼저 머지한다.
2. **T002** KRIC 기반 패키지 골격과 Chromium 생명주기·공유 limiter·예외·CI를 완성한다.
3. **T003** 소통정보와 돌발정보의 조회·모델·실패/빈 결과 구분을 제공한다.
4. **T004** CCTV 메타데이터·우회도로·도시간 소요시간을 제공한다.
5. **T005** OpenData 공개 파일의 목록·기간·첨부 및 접근 가능성을 검증한다.
6. **T006** 노드링크 자료실 기간 조회·ZIP/내역서 첨부 식별을 구현한다.
7. **T007** 제한된 다운로드·원자 저장·SHA-256 manifest·재검증·재실행을 구현한다.
8. **T008** 파일 형식 검사·ZIP 목록/안전한 선택 파싱·선택적 S3 보관을 제공한다.
9. **T009** 나머지 공식 서비스의 키 없는 대응 기능을 검증하고 가능한 것만 구현한다.
10. **T010** 전체 통합 live E2E·설치본 검증·사용 예제·지원 범위 표를 확정한다.

각 task는 이전 단계 머지 후 시작한다. 변경이 너무 크면 하위 task로 나누되 두 리뷰·live·CI
게이트를 생략하지 않는다. T005/T006 발견 모델이 T007 관리 모델의 입력이 된다.

## 완료의 의미

API와 파일에 대해 입력 검증, strict parser, 타입·예외·출처, 오프라인 fixture와 실제 Chromium
검증이 모두 있어야 완료다. 소통의 화면 범위와 전국 링크 전체를 혼동하지 않는다.
파일 목록 조회 성공은 파일 다운로드/무결성 성공이 아니다.
T001은 코드가 없으므로 실제 페이지·첨부 목록 탐색을 문서 단계의 live E2E로 인정한다.
후속 단계는 해당 공개 메서드/파일 lifecycle까지 live로 검증해야 한다.
