# 검증 사양

## 오프라인

기본 pytest는 외부 네트워크·키·설치된 브라우저 없이 실행한다. 순수 parser와 전송 경계를
fixture/mock으로 검증한다. Chromium의 실제 동작은 live suite에서 검증한다.
T002부터 compileall, mypy, pytest coverage 90%, build를 CI에 둔다.

검증 대상은 정상/정상 빈 값, 누락·잘못된 JSON/HTML, 선행 0, 숫자 비유한 값,
좌표 범위, 종료 후 호출, lazy 초기화 실패, concurrent operation, cancellation,
외부 context 소유권, limiter FIFO/취소/루프 경계다.
파일 단계는 크기 초과·길이 불일치·HTML 로그인·중단 전송·취소·경로 이탈·동시 저장·
checksum 불일치·기존 정상본 유지·ZIP traversal/bomb/CRC를 검증한다.

T006A는 TTL/LRU/동일 진행 조회 공유·실패 미보관·복사·반복 취소·종료를 검증한다.
localhost 실제 Chromium 서버의 카운터로 전송 단위 공통 버킷, 캐시 적중0회, 동일 조회1회,
접근 거부 재시도0회를 확인한다. 전체 ITS live와 로컬 회귀의 수를 따로 기록한다.

## 실제 Chromium live E2E

T001은 공개 화면 열기 → 동적 데이터/자료실 첨부 확인까지 검증한다.
T002는 설치된 패키지의 context 생성 → 공개 화면 → 정상 종료를 검증한다.
T003 이후는 공개 메서드 결과의 비어 있지 않은 필수 필드, 출처·범위·ID/단위를 확인한다.
빈 결과만 있는 응답으로 parser의 성공을 입증하지 않는다.
T007은 작은 내역서 실제 다운로드 → SHA-256 → manifest → 재실행·재검증까지 수행한다.
전체 노드링크 ZIP은 약 259MB이므로 별도 opt-in 후 한 번 내려받고 같은 파일을 재사용한다.
T010의 전체 파일 게이트에서 성공하기 전 대용량 전송까지 검증됐다고 설명하지 않는다.

`--run-live` 없이 live는 skip한다. 실행 실패와 skip을 머지 게이트 통과로 세지 않는다.
자료 변경 가능성이 있으므로 최신 자료 ID/날짜를 테스트에 상수로 고정하지 않는다.
브라우저 버전·실행 시각·범위·관찰 수를 기록하고 세션 식별자는 제거한다.
