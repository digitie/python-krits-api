- A (`/root/review_a`): 최초 `ae9ab71`의 HTTP 200 로그인/CAPTCHA 오인과
  lock/버킷 대기 timeout 제외를 P2로 지적했다. 접근 화면·필수 컨테이너 검사,
  전체 operation deadline과 대기자 자원 정리 회귀로 해결했다.
- B (`/root/review_b`): 실제 Chromium 로컬 서버로 `page.route().continue_()`의
  redirect 다음 hop 필터 누락을 재현했다. 같은 timeout 문제도 P2로 지적했다.
  CDP Fetch 요청 단계 검사로 교체하고 service worker 우회·handler/session 종료를 구현했다.
- `5c85b43`에서 두 리뷰 모두 기존 지적 해결·추가 P0~P2 없음으로 통과했다.
  B는 실제 Chromium redirect 차단 회귀를 직접 재실행해 1 passed를 확인했다.
- CI 중복 실행 억제와 SPDX 패키징 변경을 추가한 최종 `b5834fd`에서 A/B 모두

## 실제 Chromium E2E

2026-10-24 09:29 KST 실행. 최종 runtime/tests는 `5c85b43` 이후 동일하다.

```powershell
$env:KRITS_CHROMIUM_EXECUTABLE='<설치된 Chromium 실행 파일 경로>'
python -u -m pytest -m live --run-live -s -q
```

**3 passed, 62 deselected, 11.47초**, 종료 코드 0.

1. 실제 ITS 오픈데이터 소개: 키 없이 `PageSnapshot` 제목·출처·UTC 시각 확인, 종료 후 호출 거부.
2. 실제 ITS 노드링크 페이지: 주입 context에서 자체 page만 생성·정리, 호출자의 context/브라우저는
   계속 사용 가능한 것을 검증. 파일 다운로드 완료를 의미하지 않는다.
3. 실제 Chromium + 로컬 HTTP 서버: 허용 origin에서 차단 origin으로 redirect할 때
   `/forbidden` 요청이 서버에 도달하지 않음. 허용 origin의 redirect는 `/ok`까지 도달.

별도 임시 경로에 최종 wheel을 `pip install --no-deps --target ...`으로 설치한 뒤,
import 위치가 소스 checkout이 아닌 설치 경로임과 `py.typed`를 확인하고 공개 페이지 live를
추가 실행했다. 키·쿠키·원문 HTML·storageState를 증빙에 저장하지 않았다.
