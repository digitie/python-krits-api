## 변경과 회귀

Opinet의 공유 FIFO 전송 예산을 Chromium CDP의 실제 문서·자산·XHR/fetch·redirect 전송에
적용했다. 기본5RPS/capacity1, 성공 결과 TTL15초/32항목 LRU, 동일 진행 조회 공유,
자동 재시도0회다. 외부 지도/영상은 차단하고 허용 자산도401/403/429이면 page를 닫는다.
계약은 [부하 제어](../load-control.md)에 있다.

최초 두 독립 리뷰가 마지막 대기자 취소 직후 새 호출이 취소된 task를 공유하는 P2를 재현했다.
취소 task를 즉시 공유 대상에서 제외하고 새 호출은 이전 정리를 기다리도록 수정했다.
리뷰 A의 재검토에서는 replacement도 취소할 때 이전 정리 barrier를 덮는 P2를 발견했다.
키별 정리 task 집합을 유지하고 세 번째 호출까지 검증했다. 각 대기자의 시간 제한과
반복 취소·종료의 전체 정리 대기도 회귀로 확인한다.

`bd05b59`에서 A/B 모두 기존 P2 해결·추가 P0~P2 없음으로 통과했다. 이후 원격 main에
머지된 PR#4 링크 경로 기능을 통합했다. 통합 최종 SHA의 리뷰·live·CI 결과를 아래에 기록한다.

통합 소스 `1915033`에서 리뷰 B는 취소/자원과 경로 모델·파서/fixture 차이를 재검토해
P0~P2 없음, 오프라인309개와 실제 Chromium redirect1개를 직접 확인했다.
리뷰 A는 오프라인309개와 공개 JS 좌표 근거를 대조했으며 `resume.md`의 과거 PR#4
머지 대기 안내가 남은 P2를 지적했다. 현재 단계·머지 확인을 정산한 문서 수정까지 재검토해
해결 및 추가 P0~P2 없음으로 통과했다. 두 리뷰어는 `/root/review_a`, `/root/review_b`다.
